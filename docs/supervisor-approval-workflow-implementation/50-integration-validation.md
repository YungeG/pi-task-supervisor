# I／V／Q／F：汇合、真实链路与最终接受

节点状态及全部直接依赖见[施工索引](./README.md)。以下是施工与接受要求，不单独报告通过或授予权限；本轮实际代码/隔离验证按[实施契约](./01-execution-contract.md)执行，结果见[验证记录](../supervisor-approval-workflow-validation.md)。独立审阅委派、安装及业务操作仍保留各自明确授权门。

## 1. I：单写者接真实入口

I 消费 A／B／E／U 的同一 S 基线候选、针对性证据和 adapter 清单。生产文件边界按索引 I 组执行；分支文件需要修复时，必须在分支结束后明确交接给 I，或退回原节点，不能同时写。

### 汇合前核对

- 四条线消费的 K／S 身份一致，没有各自扩字段、宽松 fallback 或同名不同义的结果。
- 各线真实候选和改动文件可复现；针对性结果及未支持能力明确，写占用已释放。
- 原始确认、版本、准备阶段、执行来源与恢复的契约没有因合并变成第二份真相。
- 同一依赖／宿主条件可用。新隔离目录若缺测试工具或依赖，先核对基线和获准的供应方式，不擅自安装，也不把环境缺失当产品通过或失败。

### 必须接通的调用链

```text
真实规划／提案来源
→ A 的同版完整材料与控制身份
→ U 的显示／局部选择草稿
→ I 接入的受信原生完成与见证路径
→ A 的分别留证、reader／恢复与实际执行关联
→ B 的就绪规则＋操作前真实来源校验
→ 独立首次 Start
→ E 的有限执行／实际来源
→ A 与现有资格门消费当前证据
→ B／U 的结果、剩余门与合法下一步
```

准备阶段与待形成检查器按 C-PREP 走真实合法转换，不把普通执行、定义确认和验收混为一门，也不再制造“准备已开始但定义永远不能冻结”的循环。

I 独占接入 `human-ui.ts` 的实际完成握手和私有回应路径，以及命令、事件、Supervisor、runtime／state／scope 的共享路由。不能通过 UI 直接保存权利、把 cached action 当许可，或为兼容让未知 source／DTO 通过。

I 主要负责 adapter、调用顺序和跨线闭合，不重新实现 A／B／E／U 已拥有的核心判定。若发现实质核心逻辑缺失，应明确交回对应节点修复或调整契约，不能把大量未分配的新实现藏在“最后集成”里。

### I 的测试占用与交付

跨线测试由 I 管理，优先复用：

- `src/__tests__/human-ui.test.ts`、`human-owner.test.ts`。
- `src/__tests__/acceptance-admission.test.ts`、`acceptance-feature-admission.test.ts`、`acceptance-sdk.test.ts`、`acceptance-manual.test.ts`。
- `src/__tests__/preflight-commands.test.ts`、`workflow-gates.test.ts`。
- 共享 `src/__tests__/helpers/`、`src/__tests__/fixtures/` 及必要 smoke 入口，例如 `test/preflight-smoke.mjs`、`test/real-pi-smoke.mjs`。不把占用解释为可重写全部 fixture 或扩大 smoke 范围。

其他分项卡列出的测试保持原归属。必要新增测试和任务脚本改动由 Main 先分配，分支不自行编辑 `package.json`、锁文件或全局配置。

I 先运行最小跨线冒烟和直接边界，交付冻结整合候选及其源／契约／依赖身份。此时并不宣称所有验证通过；V 和 Q 消费的是同一候选，而非浮动工作区。

## 2. V：验证负责人，重检查只集中跑一次

V 消费 I 的冻结候选与 K 的验收矩阵，在隔离、可控的宿主／临时会话和文件中验证，不使用正在工作的业务会话、真实库或线上账号来试错。

### 两个必需正向分支

1. **已有检查器＋未生成正常产物**：启动前确认权限与已有定义，合法独立 Start，执行后实际创建产物、取版本与结果；启动前无产物通过证据。
2. **本任务创建检查器**：原范围同时覆盖合法准备与后续工作；启动准备、实际创建、按契约冻结具体定义、继续依赖工作，最终取得真实验收证据。

第二分支不能靠重建同一目标、重复 Start 或提前执行未冻结定义的依赖项过关。具体新定义需要的真实确认仍按契约取得，但不重复审批未变化业务权限。

### 必需故障与负例

- 原始控制、物理见证、两类事实、投影、Start 保存和派发各点失败，区分完整事实、可修投影与未知；不重复批准、Startup 或外部执行。
- 重开、压缩、切树、撤销、用户暂停、迟到结果与未知 close／dispatch；不补权、不自动重放、不清其他门或已耗预算。
- 缺失必需权限、待冻结／错版本定义、材料过期、多个门并存、忙碌／pending，准确参数和动作顺序。
- 复制的 NativeAnswer／draft／执行 DTO、伪造报告或退出码、错 owner／scope、路径越界／源不可得、实际版本／generation 变化、零／失败／跳过结果。
- 旧目标、旧 reader 和已声明宿主兼容：保持 legacy，不自动升级权利；不支持新事实的 reader 按冻结政策拒绝，不能静默降级成成功。
- 原生长材料、中文、窗口变化、键盘焦点／取消、详情和真实完成握手；主视图与完整范围一致。

### 成本与证据层级

先跑同一路径的小样本，验证配置、输出、失败处理和不变量，再扩大。I 的短跨线冒烟不重复完整矩阵；A／B／E／U 的局部结果不能代替整合验证。

使用已有任务入口做必要 typecheck／lint／format 与针对性测试，在冻结候选集中运行项目规定的完整门，例如 `npm run check`，不降低既有覆盖要求。具体命令和 SDK／宿主范围由 K 冻结；当前未执行，不把示例命令当已通过。

真实 CLI／PTY 自动按键只能证明该宿主路径，不证明人类身份、视觉质量或实际用户可用性。普通 SDK／复制 UI 的拒绝仍须负向验证。真实用户评价和未验证平台单独记录，不让源码模拟、网页演示或旧测试充当新流程接受。

V 的交付包括实际命令、结果、候选与环境身份、原始证据位置、失败／未知及覆盖范围。必要能力或测试不支持／失败仍是缺口，不能算完成。

## 3. Q：独立只读审阅，可与 V 并行

Q 消费同一 I 候选与冻结契约，审查权威、身份／版本、半写、reader、准备阶段、原始证据消费、UI 完整性和范围。不修改源文件、不派生 writer，不把审阅当新的批准。

源码审阅可以在 V 运行时进行；未取得的验证结果如实标记，不猜测通过。F 只有在 V／Q 都覆盖同一最终候选、发现已处置后才可接受。代码改变使相关审阅或证据失效时，复核实际受影响范围，不能照抄旧结论。

Q 仅在未来明确允许的委派／执行方式下启动；失败不静默切换其他 CLI 或模型。当前没有启动本节点。

## 4. F：Main 最终核对，不自动提交发布

F 不再实现另一份状态机，负责核对：

- K／S 到 A／B／E／U、I、V／Q 的身份、契约及改动范围闭合；必要分支和故障实际覆盖。
- 主控独立复核发现与相应验证；必要修复更新候选，按影响和既有门重新取得证据，不因旧绿灯省略。
- 单独保留真实用户可用性、未支持能力、自动化证明边界和剩余风险，不宣称未做的视觉／生产验收。
- 记录实际候选、执行结果、报告及接受范围；不是只记录一个 PASSED 字符串。

F 完成只表示获准范围内的源码候选接受。提交、推送、安装、重载、发布及业务运行仍按明确授权执行；不得自动变更当前 Pi 配置或运行会话。
