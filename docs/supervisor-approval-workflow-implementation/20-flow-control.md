# B：实际资格与下一步一致

状态、依赖和文件归属见[施工索引](./README.md)。B 消费 S 的实际接口，不等待 A／E／U 各自实现结束；真实入口适配归 I。

## 结果

对同一份有来源的当前事实，给出明确的下一动作、参数、执行者、影响和剩余阻塞；不再笼统地把 active 当作可执行、把 paused 当作一律 recover。

显示是只读投影，不创建授权或实际执行资格。已知事实下不应推荐必然被其他门拒绝的动作；用户点击前状态变化造成合法拒绝时，明确说明变化，不能静默重试或补授权。

## 输入／输出

- 输入：C-ACT 规定的当前 owner／目标、规划／确认／定义状态、宿主 idle／pending、用户暂停、撤销、日志／回执问题、未知执行与其他门；字段、来源、unknown 表示及返回值由 K 冻结。
- 输出：纯资格判断与对应的人类下一步描述。只给准确存在的参数，不生成虚构 proposal／decision ID。
- `HumanMaterial` 或文案不是输入权威；不能从一段“已批准”的字符串反推真实闭包。

## 源码与占用

B 独占 `src/flow.ts`，重点为 `FlowFacts/flowFacts`、`resumeControlIssue`、`ordinaryResumeIssue`、`nextFlowStep` 与状态格式化。

测试占用为 `src/__tests__/flow-commands.test.ts`；必要新增纯资格测试文件由 K／S 分配。不改共享 command／native UI fixtures。

`src/commands.ts`、`src/events.ts`、`src/supervisor.ts` 及 runtime 的真实动作接入归 I。B 提供精确调用点和所需事实清单，不能为了单线通过在这些共享文件里接一套旁路。

## 判定要求

1. 区分尚未准备、必需权限缺失、定义未确认／待形成、用户主动暂停、技术故障、结果未知与容量／环境不支持。
2. 同时存在多个门时给合法处理顺序及其他阻塞；解除一门不表示自动解除全部。
3. 只有 C-PREP 允许的准备范围才可推荐推进；不能为了冻结检查器推荐重建同一目标、重复 Start 或未授权执行。
4. 读状态不采用 owner、不修复投影、不重扫全历史／抓源文件版本、不调用模型、进程或执行器。
5. 缓存投影不能独立证明当前性。I 在实际动作前取得真实当前依据，复用相应规则并保留原始来源／见证校验，不把“按钮可点”当新权利。
6. 保持旧无新协议目标的实际行为；不把旧状态显示成新联合审批已完成。

## 本线最小验证

覆盖权限已批但定义未绑定、暂停且定义未绑定、决策与故障并存、已确认但投影缺失、未知执行、忙碌／pending、过期材料以及普通合法继续。

检查准确参数、执行影响和其他门均在输出中；known blocker 不被通用 recover 掩盖；查询不产生写入／派发。用真实 B 入口和来源明确的事实 fixtures 验证，不能以文字包含某个单词代替资格断言。

本线只运行本地 `node_modules/.bin/vitest run src/__tests__/flow-commands.test.ts` 及 K 冻结的直接边界检查；这是未来验证入口，不表示当前新场景已存在或已运行。真实命令和 native 控制的组合证明由 I／V 完成。
